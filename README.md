# 宝宝喂养记录

[![Tests](https://github.com/yalerong/baby-feeding/actions/workflows/test.yml/badge.svg)](https://github.com/yalerong/baby-feeding/actions/workflows/test.yml)

基于微信小程序和微信云开发的家庭育儿记录工具。把喝奶、大便、辅食、成长和疫苗记录放在一起，方便家人共同记录和查看。

> 本项目用于家庭记录与辅助整理，不替代医生、营养师或儿保机构的建议。

## 功能概览

| 模块 | 当前功能 |
| --- | --- |
| 今日记录 | 母乳、奶粉、大便、辅食和照片；快速录入、编辑、删除、历史补录与批量补录 |
| 喂养回顾 | 近距离喂养提醒、昨日记录审查，按近期记录分别计算白天和夜间间隔参考 |
| 生长曲线 | 身高、体重、变化值和百分位；固定使用 WHO 男宝标准，历史记录可分批展开 |
| 发育里程碑 | 6、9、12 个月 CDC 观察清单，记录观察结果、日期与备注，提供陪玩建议和儿保沟通摘要 |
| 辅食菜单 | 按月龄生成周/月安排，替换菜品，自定义菜与家庭菜谱库，排除已标记的过敏食材 |
| 食物解锁 | 严格/宽松两种试吃模式，手动解锁、撤销打卡、异常备注，与辅食记录联动 |
| 喂养统计 | 7、14、30、90 天及全部记录；月度汇总、单月明细、奶量与母乳占比 |
| 疫苗计划 | 按出生日期生成计划，记录接种状态、调整日期和自定义疫苗 |
| 家庭共享 | 使用相同 `familyCode` 共享云端记录；部分页面实时同步，其余进入页面或刷新时更新 |

### 生长与观察

- WHO 曲线固定为男宝 0–5 岁参考标准。宝宝记录用无圆点的实线，P50 用虚线，P3–P97 用浅色参考带；横轴按真实月龄排列，单位与刻度分开显示。
- 最新身高、体重可显示「约第 N 百分位」。只有一次测量时显示短横线，不虚构趋势；完整历史始终参与曲线和最近摘要计算，列表先显示 20 条并可继续展开。
- 体重轴默认 0–20 kg、每 5 kg 一个刻度，参考带超出时适当扩展。超出当前纵轴的记录用顶部三角提示，原始数值仍保留在历史中。
- 里程碑从「生长 → 发育里程碑」进入，分四个领域记录「已观察到 / 还没观察到 / 不确定」。目前收录 6、9、12 个月三个节点；7–8 个月默认回顾 6 个月清单，可手动预览后续节点。

### 喂养与试吃

- 单条录入、补录和批量补录会检查临近喂养，包含前一天记录；1 小时内的疑似重复会提醒确认，昨日记录可集中回顾。
- 间隔参考使用过去 10 个完整自然日，不包含今天；白天、夜间分别计算，保留整夜睡眠间隔。样本不足 4 段时显示「暂用默认」。
- 严格试吃模式为一次一种、连续 3 天；宽松模式可同时记录多种食材，按累计 3 天解锁。两种模式都保留疑似过敏排除和异常备注。
- 保存辅食记录会等待试吃同步结果；如果仅试吃同步失败，会明确提示并提供重试，不会再次新增同一条喂养记录。

## 打开与加载优化

首页、统计、生长、疫苗和里程碑会先显示同家庭、同查询的近期快照，再后台刷新。缓存展示期限为 5 分钟，命中也会重新校验；里程碑有未保存编辑时先保护草稿。离开页面后，迟到读取不会继续渲染或重新打开监听。

录入页只在启用辅食时加载相关候选；菜品详情先显示缓存，后台核验不覆盖编辑。详情和里程碑在核验未完成或失败时保留内容，并保护保存或摘要导出等操作。

| 固定数据集下的对比 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 纯奶录入首开云请求 | 5 次 | 1 次 |
| 生长 500 条记录，首屏前分页读取 | 26 次 | 0 次，直接使用监听初始快照 |
| 统计 365 天，月份首屏 `setData` | 178,850 字节 | 2,862 字节 |
| 菜单周视图 `setData` 总量 | 128,098 字节 | 16,926 字节 |

以上是实际页面方法在固定模拟数据下的请求计数和传输体积，不是手机启动时延；尚未进行真机测速。实现、测试与已知边界见 [性能优化记录](docs/performance-optimization.md)。

## 快速开始

准备微信开发者工具、自己的小程序 AppID 和云开发环境。本地测试需要 Node.js 和 npm，GitHub Actions 使用 Node.js 20。

1. 克隆或下载本仓库，在微信开发者工具中导入根目录，使用自己的小程序 AppID。
2. 在云开发控制台创建或选择云环境。
3. 复制 [config.local.example.js](config.local.example.js) 为 `config.local.js`，填写配置：

```javascript
module.exports = {
  cloudEnv: 'your-cloud-env-id',
  familyCode: 'YOUR_RANDOM_FAMILY_CODE',
  cryAlertTemplateId: '' // 可选；哭声提醒入口默认关闭
}
```

4. 在开发者工具中为 `cloudfunctions/` 选择该云环境；如果提示“请选择一个云环境”，先检查这里与 `cloudEnv` 是否一致。
5. 部署下面的日常云函数。首次部署可右键函数目录，选择“创建并部署：云端安装依赖”。

| 用途 | 云函数 |
| --- | --- |
| 喂养记录 | `addRecord`、`updateRecord`、`deleteRecord`、`getRecords`、`batchFeeding` |
| 首页与回顾 | `homeSummary`、`dailyReview`、`supplement` |
| 统计与生长 | `getStats`、`growthRecord` |
| 菜单与试吃 | `weeklyMenu`、`foodTrial`、`customDish` |
| 疫苗与里程碑 | `batchVaccine`、`milestoneRecord` |

6. 按下文核对数据库集合和访问权限，编译小程序，在首页设置宝宝生日。家人使用同一套云环境和相同 `familyCode` 即可共享数据。

`homeSummary` 聚合当天记录、昨日回顾和补剂状态。没有间隔建议缓存时，建议使用独立后台请求，不阻塞今日记录。聚合函数未部署时，首页会回退到现有独立接口。

以下云函数是历史修数用的一次性脚本，日常不需要部署：`fixDates`（修正日期格式）、`fixFamilyCode`（批量改家庭码）、`initFamily`（初始化家庭）。

如需使用哭声订阅提醒，再部署 `cryAlertSubscription` 和 `cryAlertWebhook`，并按各自的 `config.js.example` 配置密钥与模板。

> 首页的「哭声提醒」入口默认关闭（`pages/index/index.js` 的 `cryAlertEnabled`）。如需启用，完成对应云端配置后将其改为 `true`，再重新编译前端。

### 从旧版升级

- 更新前端后重新编译；本次云端读取优化还需要部署 `homeSummary`、`getRecords`、`getStats`。推送 GitHub 只更新仓库，Actions 只运行测试，不会自动部署微信云函数。
- 仅更新已有函数代码时可使用开发者工具的代码增量部署，避免无意重新安装 `wx-server-sdk: latest`。首次部署仍需安装依赖。
- 菜单草稿和跳转快照现按家庭与周隔离。无法确认归属的旧格式数据原样保留，但不会自动读入当前家庭；升级前有未保存菜单时，应先在旧版保存。
- `config.local.js`、`project.private.config.json` 和运行状态目录 `.omx/` 不提交到 Git。仓库不包含可直接使用的个人云环境或家庭码。

## 云数据库集合

核心集合如下：

| 集合 | 用途 |
| --- | --- |
| `feeding_records` | 喝奶、大便、辅食记录 |
| `food_trials` | 连续/累计试吃、手动解锁与疑似过敏状态 |
| `daily_reviews` | 家庭共享的昨日记录审查确认状态 |
| `weekly_menus` | 家庭周菜单 |
| `custom_dishes` | 家庭菜谱库（家长自己写的菜，跨周复用） |
| `families` | 家庭级设置（`trialMode` 试吃模式）；未建时 foodTrial 按严格模式运行，切换模式时会自动创建文档 |
| `growth_records` | 身高、体重记录 |
| `milestone_records` | 家庭共享的发育里程碑观察结果、日期与备注（首次使用自动建集合） |
| `vaccine_records` | 疫苗计划与接种记录 |
| `supplement_records` | 营养补充剂记录（如启用） |

`feeding_records` 可带 `images`（云存储 fileID，最多 3 张，录入页 `components/photo-uploader` 上传，首页列表显示缩略图、点开预览；删除记录或编辑时去掉的照片会尽力清理云存储）。

`feeding_records` 的辅食字段为：`solidFood`、`solidFoodDishId`、`solidFoodDishName`、`solidFoodGrams`、`solidFoodFoods`（自定义菜带的规范食材名数组，菜库菜为空）。云函数会拒绝“已勾选辅食但名称为空或克数不大于 0”的记录。

<details>
<summary>展开辅食与试吃联动的详细规则和已知限制</summary>


- 手填辅食名会按菜库食材词典识别（“胡萝卜泥”→胡萝卜，“苹果燕麦糊”→苹果+燕麦），识别出的食材再走“一次只试一种、连续 3 天解锁”的自动打卡；识别不到就提示手动记，不会把菜名当食材存进 `food_trials`。
- 修改或删除辅食记录会回退它自动打的那次卡（`food_trials.logSources` 按日期记录每天是哪条记录打的卡，`lastLogRecordId` 为最后一天的快照；解锁页手动打的卡、同一天还有别的记录吃到该食材、或同日记录拉取失败时都不回退）；补录昨天及更早的辅食也会打卡，但早于该食材最近一次试吃日期的补录不打。已知限制：①删掉连续试吃中间某一天的记录不会重算天数，需要到解锁页手动撤销；②回退前的"同日其它记录"检查与回退本身不是一个原子操作，两位家长在同一秒内一个删、一个加同一食材的记录时可能少一天打卡，个人家庭使用场景不处理。
- 标记「疑似过敏」时可以顺手填症状备注（`food_trials.allergyNote` / `allergyDate`），卡片上显示，恢复推荐后备注保留。
- 试吃有两种模式，存在 `families.trialMode` 全家共用，「食物解锁」页顶部切换：严格模式=一次只试一种、连续 3 天；宽松模式=可同时试几种、不要求连续、累计 3 天。`food_trials.logDates` 记录本轮打卡日期，撤销时回到列表里的上一天。
- 「食物解锁」页可以自己添加菜库没有的食材（`foodTrial` 的 `add` 动作，建档 0 天不占用“当前连续试吃”）。所有已解锁食材统一提供「记录异常」和「移除」；移除（`remove`）会删除该食材的试吃档案和解锁状态，保留首页辅食记录，菜库内食材之后按未解锁处理，菜库外条目从列表消失。未解锁的菜库外条目仍可移除。撤销首日记录改为回到 0 天而不删档。
- 之前已经试吃通过但漏登记的食材，可点「手动解锁」。该操作单独标记 `manuallyUnlocked` 和登记日期 `unlockedDate`，不虚构历史试吃日期；编辑或删除旧喂养记录不会撤销这项手动解锁。疑似过敏项须先恢复推荐，才能补登记。
- 保存辅食后会等待试吃同步结果再返回；严格模式被其他进行中的食材挡住、补录日期过早或同步失败时明确说明「记录已保存，试吃未计入/未同步」，避免误以为辅食没有保存而重复录入。同日重复打卡、已解锁食材不算失败。同步失败时可点「重试同步」，只重试同一条已保存记录的试吃同步，不再次新增或修改喂养记录。
- 当前及进行中的试吃优先显示；严格模式的未完成试吃断档后提示需重新记录 3 天，进度按重新开始展示，保留数据库中的原始历史计数。宽松模式按累计天数展示，已解锁项保持解锁。
- 周菜单保存时记录当时的已解锁食材快照（`weekly_menus.unlockedFoods`）。之后再解锁新食材，打开本周会提示"刷新今天之后"，只重排今天以后的常规餐位，过去和今天的安排不动，刷新后仍需手动保存。
- 菜单大厅里可以“自己写一道”自定义菜：保存时先进家庭菜谱库 `custom_dishes`（云函数 `customDish`，按 `_id`/菜名去重），再写进本周 `weekly_menus`；大厅顶部「我的菜谱」可复用或删除库里的菜；录入页常吃列表按 历史 → 本周自定义菜 → 菜谱库 → 菜库 的顺序填满，选中时把菜的规范食材带进记录。

</details>

## 数据与隐私

发育里程碑清单参考 [CDC 6个月清单](https://www.cdc.gov/act-early/digital-online-checklist/6-months.html)、[9个月清单](https://www.cdc.gov/act-early/digital-online-checklist/9-months.html) 与 [12个月清单](https://www.cdc.gov/act-early/digital-online-checklist/1-year.html)，中文内容核对于2026-10-14。清单用于日常观察和儿保沟通，不能替代专业发育筛查；「已记录」只是记录数量，不是能力评分。每项保存最新一条观察，可修改日期和备注；不会自动勾选聊天中提到的能力，也不会虚构首次达成日期。家人下次进入页面或下拉刷新时读取共享结果，同一项同时修改时以后保存的内容为准。陪玩建议只按当前月龄和观察状态匹配，尚未接入大模型，不分析备注。产品调研、来源与取舍见 [里程碑调研记录](docs/milestone-research.md)。

新增功能需部署 `cloudfunctions/milestoneRecord`（沿用项目已有的 `wx-server-sdk`），然后重新编译小程序。集合只需云函数访问，建议在云开发控制台将 `milestone_records` 权限设为「仅管理端可读写」。

- `familyCode` 是家庭数据分组标识。请使用不易猜测的随机字符串，不要使用默认值或公开信息。
- 云函数会按 `familyCode` 查询和写入数据；为防止串号，家庭成员应使用同一个家庭码。
- 日期统一按北京时间（UTC+8）计算，与手机所在时区无关；跨时区使用时「今天」仍以北京时间为准。
- 疑似过敏标记只是记录和菜单过滤工具；若出现不适或疑似过敏反应，请及时咨询专业医疗人员。

## 开发校验

根目录测试不需要额外安装 npm 依赖，运行：

```bash
npm test
```

本次更新已通过 **45/45 个测试文件**，涵盖记录校验、分页、日期、辅食与试吃联动、家庭缓存隔离、后台响应竞态、图表及里程碑。GitHub Actions 会在推送 `main` 或提交 Pull Request 时运行同一命令。

页面改动还使用微信自带编译器检查 WXML/WXSS，并以 320px、375px 浏览器预览检查布局；这些检查不替代真机验证。修改云函数后仍需部署对应函数，修改前端后重新编译。

<details>
<summary>历史试吃漏计的离线修复工具</summary>

历史漏计可用离线脚本生成指定食材的修复文件（支持 JSON 数组或 JSONL 导出，不连接云数据库）：

```bash
node scripts/repairFoodTrials.js feeding_records.json food_trials.json repair-output --food 红薯 --food 菠菜 --unlocked 苹果 --unlocked 香蕉
```

`--food` 根据同一家庭的喂养记录补回截至最近打卡日的连续日期，同一天只计一次，不跨家庭、不覆盖疑似过敏；`--unlocked` 仅用于家长已确认之前试吃通过的食材。脚本保留原字段及已有手动打卡来源，生成选中条目的 `food_trials-repaired.jsonl`、原始备份 `food_trials-original.jsonl` 和前后对照 `food_trials-repair-plan.json`，不会修改输入文件或覆盖已有输出。应用到云端前需核对最新条目与 `before` 一致，只更新这些 `_id`，不要清空整个集合或用旧快照覆盖后来新增的打卡。

</details>

# 打开与加载性能优化

本轮保留微信小程序、现有云函数合同及数据写入流程，优化数据读取和视图传输。`app.json` 原本已启用 `lazyCodeLoading: requiredComponents`，未把它算作新增收益。

## 改了什么

- 首页、统计、生长、疫苗、里程碑共用 `utils/pageSnapshot.js`：按家庭和查询条件隔离，先显示五分钟内的快照，随后重新读取云端；里程碑有未保存编辑或正在保存时先保护草稿。同键进行中的请求合并；内存最多 20 项，每页面磁盘只留一个快照。
- 快照只保存展示所需的原始数据；首页不缓存补剂确认和昨日审查结论。保存、修改、删除成功后失效相应快照。磁盘写入/删除按页面串行执行，过期请求不能恢复已经失效的缓存。
- 首页的今日记录不再等待近十天的喂奶建议扫描。首次没有建议缓存时使用两个独立并发读取，命中建议缓存时仍只需一次聚合读取。确定聚合函数不存在后，本次页面会话直接走已有回退路径；普通网络错误仍允许重试。
- 生长页直接使用实时监听的初始完整数据，不先串行分页再重复监听。监听不可用、报错或八秒没有初始事件时，单次回退到完整分页读取。历史先显示 20 条，可继续展开；曲线和最近摘要始终使用全部记录。
- 统计完整每日数据保留在页面私有字段；月份视图只传月摘要，进入某月才传该月明细。同范围重复点击不再重新请求。疫苗记录、筛选结果和摘要合并为一次视图更新。
- 菜单的试吃读取和周菜单读取并行，生成仍等待最新解锁与过敏限制。整月、菜库和完整试吃卡片在进入相应视图时才构建；日期导航不再重复携带整天的菜品数据。
- 离开页面后，迟到响应不再更新视图、写入展示快照或重新打开监听。首页图片增加懒加载。
- 云端 `homeSummary`、`getRecords` 将当天记录与上一条喂奶并行读取；`getStats` 仅读取统计和稳定排序所需字段，保留完整分页。

## 同一组基准的前后结果

使用真实页面方法与工具模块，在隔离 VM 中模拟微信接口、网络响应和本地存储。两次使用同一时间、同一数据集；以下是调用计数与 UTF-8 传输体积，不是手机或云端耗时。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 生长 500 条，首次显示前的分页 `get` | 26 次 | 0 次，使用一次监听初始快照 |
| 生长首次完整数据的重复渲染 | 2 次 | 1 次 |
| 生长页首轮可见历史行 | 500 行 | 20 行，支持继续展开 |
| 统计 365 天，月份首屏 `setData` | 178,850 字节 | 2,862 字节，减少约 98.4% |
| 统计月份首屏发送的每日明细对象 | 1,095 个 | 0 个，进入月份后再发送 |
| 菜单周视图 `setData` 总量 | 128,098 字节 | 16,926 字节 |
| 试吃请求未返回时，周菜单请求是否已开始 | 否 | 是 |
| 周视图额外生成整月计划 | 1 次，共 4 周 | 0 次 |

新增七份无依赖行为测试：`pageSnapshot`、`homeLoading`、`listLoading`、`statsLoading`、`statsProjection`、`menuLoading`、`cloudReadPerformance`。覆盖缓存过期/隔离/失效、持久化顺序、并发读取、隐藏与乱序响应、分页回退、统计口径与可见数据量。

最终 `npm test` 为 **41/41 个测试文件通过**；24 个变更 JS 的语法检查通过，五个主页面的微信 WXML 编译、WXSS lint 和编译通过，差异检查通过。独立代码审查发现的“聚合未返回时切日期会漏查昨日回顾”已补回归并修复，最终审查为 CLEAR。

320/375px 的统计月份、单月和生长历史共六个浏览器预览场景没有横向溢出；生长历史可从20条继续展开到100条，完成后按钮消失。同一 fixture 的 WHO 画布前后 SHA-256 一致。视觉检查95/100；菜单使用原生编译及行为测试验证，本轮没有新增菜单浏览器截图。

## 第二轮补全：录入、详情、里程碑和家庭草稿

- `pages/add/add.js`：纯奶首开仅取必要喂养记录，实际云调用从 **5 次降至 1 次**。辅食首次启用或编辑辅食记录时才并行读取候选和试吃状态；复用已完成候选，返回时重新核验试吃，晚到结果不覆盖当前菜名、克数和已选食材。保存与试吃联动仍等待必要云端结果，不提前报成功。
- `pages/menuDish/menuDish.js/.wxml`：本家庭、本周的合法缓存或草稿在云请求返回前显示；后台读取不重建已编辑表单。食材/菜单未核对完成或失败时禁止保存，保留内容并提供重试；保存后清理仅使用请求发起时捕获的家庭键。
- `pages/milestones/milestones.js/.wxml`：缓存先显，保留选择的月份和展开组；同步期间和失败时清单仍可读，编辑、保存与摘要导出在核验成功前受保护。同上下文未保存编辑或正在保存时暂停刷新；隐藏期间保存成功只在首次返回时恢复一次。
- `utils/menuStorage.js` 与菜单、详情、录入三处调用统一 `familyCode + weekStart` 命名空间。A家庭保存晚返回不能删除B家庭草稿或改写B家庭页面。无法确认归属的旧格式草稿和跳转快照原样保留，不自动读取、迁移或删除，避免把旧内容认领到错误家庭。

新增 `addLoading`（9项）、`menuDishLoading`（16项）、`milestoneLoading`（12项）、`menuStorage`（键隔离和迟到保存）四份真实行为测试。整合后 **45/45 个测试文件通过**；33 个变更 JS 语法检查通过，本轮四个页面的微信 WXML 和 WXSS lint/编译通过。独立代码审查为 CLEAR。未新增依赖。

详情页核验中/成功/失败、里程碑同步中/失败，分别在320/375px共十个真实模板预览场景检查通过：没有横向溢出或浏览器错误，核验前保存禁用、核验后保留编辑并允许保存，缓存清单在同步或失败时均可见。视觉检查96/100，尚未手机真机验证。

## 生效范围

前端改动重新编译即可使用，不依赖新增云函数。三个既有云函数的读取优化需要重新部署 `homeSummary`、`getRecords`、`getStats` 才会在云端生效；本轮没有部署或改动真实云数据。

部署条件检查发现开发者工具 CLI 服务端口关闭；尝试启用后，现有 IDE 实例仍返回 `wait IDE port timeout`，未能读取并确认目标云环境。部署状态仍是未完成，不能把本地编译或测试当作已经上线。服务恢复后优先增量部署三个 `index.js`，避免普通部署重新解析 `wx-server-sdk: latest`。

首次没有任何快照时仍依赖网络和云函数冷启动。当前证据来自自动化行为测试、接口计数与浏览器静态预览，尚未进行手机真机测速，不能据此换算打开速度提升百分比。
